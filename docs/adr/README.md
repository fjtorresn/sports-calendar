# Architecture Decision Records (ADRs)

An ADR records **one** architecture decision: its context, what was decided, and its
consequences. ADRs are never rewritten: if a decision changes, a new ADR **supersedes**
the old one, so the history of why it changed is preserved.

Format based on [Michael Nygard](https://cognitect.com/blog/2011/11/15/documenting-architecture-decisions).
Possible statuses: `Proposed`, `Accepted`, `Superseded by NNNN`.

To add one: copy the structure of an existing ADR and use the next number.
